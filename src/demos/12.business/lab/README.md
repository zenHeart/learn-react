# 工单模块交付

案例性质：作者设计的合成业务场景，不是招聘公司的内部题目或真实客户数据。需求依据是公开岗位对 React/TypeScript 界面交付、调试与可靠性的要求，例如 [Highbeam Frontend Engineer](https://jobs.ashbyhq.com/highbeam/2b4f6606-1289-4e85-8227-1290fe12f7f4)。岗位采样日期见项目岗位证据；本案例不声称代表市场频率。

前置能力：受控输入、派生列表、稳定 key、事件处理、HTTP 状态码、基础测试。运行环境：锁文件约束的 React 19.1.0、Node 22、pnpm 9.15.4。页面入口：`/#/labs/service-desk`（项目 Pages 部署时加 `/learn-react` 前缀）。

## 任务与交付

给客服交付可创建、搜索、筛选和切换状态的工单模块。必须证明无效输入不会写入、响应丢失后重试不会重复创建、过期版本不会覆盖他人修改、空态和错误能够通过键盘及辅助技术理解。提交组件、服务契约、自动化测试、键盘操作记录和取舍说明。

页面将故障控制与反馈放在一起。关闭答案独立实现时，可只保留以下验收表：

| 情景 | 可观察结果 |
| --- | --- |
| 空白标题、非法优先级 | 422，列表不变 |
| 服务提交后丢失响应，再用相同键重试 | 同一 ID，只有一条记录 |
| 同一键携带不同内容 | 409，原记录不变 |
| 旧版本写入 | 409，保留新版本；刷新后明确重试 |
| 搜索不存在的标题 | 可解释空态，清空查询后恢复列表 |

递进方式：先运行示范，再补全版本判断；从空文件独立实现；对故障注入排错；迁移到库存扣减；三天后无提示复测。一次浏览或测试通过不代表学习者掌握，学习者记录需注明是否查看答案、使用提示及迁移结果。

## 执行验证

```sh
node --test src/demos/12.business/lab/service.test.mjs
node src/demos/12.business/lab/server.mjs
```

第二条启动仅绑定 `127.0.0.1:4319` 的教学 HTTP 服务。支持 `GET /tickets`、`POST /tickets`（`Idempotency-Key` 请求头）和 `PATCH /tickets/T-1`（`status`、`expectedVersion`）。测试实际打开本地端口并发出 HTTP 请求，不用 mock 代替接口边界。浏览器页面使用同一领域服务的内存适配，演示响应丢失；它没有连接此本地 HTTP 服务。

## 模型边界和迁移题

内存 Map 不跨刷新、进程或实例持久化，检查与写入仅在此同步单进程模型内连续执行。生产实现需要数据库事务/条件更新、唯一约束、身份与对象级授权、幂等记录过期策略。列表查询应支持分页和服务端过滤。本例没有这些生产能力，也没有声称上线可用的后端。

迁移题：两台服务器同时处理相同幂等键时该怎样保证只有一条写入？不能回答“前端禁用按钮”。给出唯一约束或事务方案、冲突响应和可运行的并发测试，然后解释请求指纹与敏感字段的处理。
