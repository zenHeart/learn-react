核心概念

React Fiber 是 React 16 引入的新协调引擎，它将渲染工作拆分成可中断的单元。 理解 Fiber 节点与组件实例的映射关系，是深入 React 内部工作原理的关键。

💡 关键洞察

函数组件没有传统的"实例"。React 通过 type 属性指向组件函数， 通过 memoizedState 存储 Hooks 状态，这就是函数组件的"虚拟实例"。

// 类组件：有真实实例 const classFiber = { type: ClassComponent, stateNode: new ClassComponent(), // ← 指向类实例 tag: 1 }; // 函数组件：无实例 const functionFiber = { type: FunctionComponent, // ← 指向组件函数 stateNode: null, // ← 函数组件不需要 memoizedState: { ... }, // ← Hooks 状态在这里 tag: 0 };

Hooks 状态存储机制

函数组件的 Hooks 状态存储在 memoizedState 属性中， 它是一个链表结构，每个节点对应一个 Hook。

点击"查看 Hook 链表"开始演示

useState 数据流

// 1. 首次渲染 const fiber = { memoizedState: { memoizedState: 0, // ← useState 初始值 next: null } }; return [0, dispatch]; // 返回 [state, setState] // 2. 调用 setState(5) dispatch({ action: 5, next: null }); // ↓ 调度更新 scheduleUpdateOnFiber(fiber); // 3. 重新渲染 hook.memoizedState = 5; // ← 更新状态值 return [5, dispatch];

⚠️ 重要规则

Hook 调用顺序必须保持一致！ 因为 React 通过链表索引来匹配 Hook， 条件语句中使用 Hook 会导致索引错乱。

updateQueue 结构

const updateQueue = { baseState: 0, // 基础状态 firstUpdate: null, // 第一个挂起的更新 lastUpdate: null, // 最后一个挂起的更新 lanes: 0, // 优先级车道 }; const update = { action: 5, // setState 的参数 next: null, // 链表下一项 lane: 0 // 优先级 };

不同类型 Fiber 节点对比

React 使用不同的 WorkTag 来标识 Fiber 节点类型，每种类型有不同的数据结构。

🔵 FunctionComponent (tag=0)

type: MyFunctionComponent  // 指向函数
stateNode: null             // 无实例
memoizedState: Hook链表     // 存储 Hooks
elementType: 原函数引用     // 原始类型

🟡 ClassComponent (tag=1)

type: MyClassComponent      // 指向类
stateNode: 类实例           // 有实例
memoizedState: this.state   // 类状态
elementType: 原类引用       // 原始类型

🟢 HostComponent (tag=5)

type: 'div'                 // DOM 标签
stateNode: <div> DOM元素    // 真实 DOM
memoizedState: null        // 无状态
elementType: 'div'          // 标签名

🔵 HostRoot (tag=3)

type: null                  // 根节点无类型
stateNode: FiberRoot       // 指向根节点
memoizedState: null        // 根状态
child: App Fiber           // 子树入口
