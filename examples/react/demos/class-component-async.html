区别: 使用回调可以确保在读取 this.state 时，状态一定是最新值。 
// setState 回调用法
this.setState(
  { data: result },
  () => {
    // 状态已更新完成，此时可以安全读取

  }

3. AbortController 取消请求

Fetch 请求取消

使用 AbortController 在组件卸载时取消正在进行的网络请求。

Ready
class DataFetcher extends React.Component {
  componentDidMount() {
    this.controller = new AbortController();
    fetch(url, { signal: this.controller.signal })
      .then(res => res.json())
      .then(data => this.setState({ data }))
      .catch(err => {
        if (err.name !== 'AbortError') {
          // 处理实际错误
        }
      });
  }
  componentWillUnmount() {
    this.controller?.abort();
  }
}

4. 方案对比

mounted 标志位方案

优点简单直接，适用于所有异步操作
缺点无法取消正在进行的网络请求
注意定时器需要单独清理
_mounted = false;
componentDidMount() { this._mounted = true; }
componentWillUnmount() { this._mounted = false; }
// 异步回调中使用
fetch(url).then(data => {
  if (this._mounted) this.setState({ data });
});

AbortController 方案

优点可取消网络请求，节省带宽
缺点不适用于定时器、订阅取消
注意需要检查 AbortError
_controller = null;
componentDidMount() {
  this._controller = new AbortController();
  fetch(url, { signal: this._controller.signal });
}
componentWillUnmount() { this._controller?.abort(); }

组合方案（推荐）

优点既可取消请求，又有状态更新保护
注意需要额外代码，但最安全
推荐! 同时使用 mounted 标志和 AbortController

5. 闭包陷阱

setInterval 中的闭包问题

setInterval 回调中的 this.state 可能不是最新值（闭包捕获了旧值）。

0
闭包陷阱! 计数器停止增长，因为 setInterval 闭包捕获了初始状态。

代码对比

// 错误：闭包捕获了初始 this.state.count
setInterval(() => {
  this.setState({ count: this.state.count + 1 });
  // this.state.count 永远是初始值 0!
}, 1000);
// 正确：使用函数式更新
setInterval(() => {
  this.setState(prevState => ({ count: prevState.count + 1 }));
  // prevState 是最新状态!
}, 1000);
